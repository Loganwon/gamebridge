# GameBridge 跨游戏 AI 转换器

GameBridge 的目标是让用户描述“把来源游戏的内容与交互带入宿主游戏”，由 AI 分析资源和接口、规划转换任务，逐步生成适配工程、构建 Mod 并在真实宿主中验收。转换对象包括角色、武器、招式、规则和资源，交付物是改造真实游戏的 Mod。

**0.8.0 Alpha 新增转换执行内核：有界行为规格 → 锁定 C# 工程 → 实际 SDK 隔离编译 → 逐步结果验证。** 工程和二进制通过独立文件产物传递，通用工具按工具链/格式注册。三种自有行为结构及一次修改已在内核层验证；游戏适配器仍为空，尚无可安装 Mod 或已验收游戏组合。[执行内核与边界](docs/execution-kernel.md)

**0.8.1 Alpha 增加同规格 Squirrel 后端与通用宿主预检合同。** SuperTux 0.7.0 官方 x86_64 版原生 VM 已执行 40 步内核向量，错误脚本被真实编译器拒绝；介绍页与可操作窗口未打通，计时、位移和真实按键验收仍阻断。本轮模型调用 0，不登记游戏支持。[本轮结果与失败记录](docs/host-preflight.md)

## 本地启动

需要 Node.js 24+，无第三方 npm 运行依赖。

```sh
npm test
npm run dev
```

打开 `http://127.0.0.1:4173`。将 `.env.example` 复制为本地 `.env`，在本机填写 `DEEPSEEK_API_KEY`；也可在本地工作台临时输入 Key。宿主填写实际承载玩法的游戏，来源填写希望迁入内容的游戏，两者统一使用 `hostGame` / `sourceGame`。

选择内容类型，输入完整需求，再发起 AI 分析。工作台展示逐项需求、资源和接口缺口、待澄清问题，以及后续任务的依赖与阻断原因。可导出转换计划 JSON；它不是 Mod 安装包。

“单次需求分析”调用一次模型；“多 Agent 协作”正常调用五次，先需求规划，再并行来源/宿主分析，随后转换设计和独立方案审查。角色输出分别校验并传递上游产物；它们均是未核验的分析建议，没有浏览器、资源处理、代码或游戏执行工具。

协作预算由本地调度器在每次调用前持久化预留，不自动重试收费任务。可载入本机任务、取消、导出记录或明确恢复；重启不会自动重发模型请求。恢复已完成任务不会重跑，中断任务重放须明确勾选且有预算。Key 需要重新提供，不保存在运行记录中；默认 Key 仍绑定配置的 API origin。[恢复与权限边界](docs/task-runtime.md)

macOS 可运行 `npm run verify:sandbox` 验证通用底座隔离边界；`npm run verify:execution` 通过真实 SDK 编译并验证行为内核；`npm run verify:diagnostics` 检查一次受控真实 C# 错误。它们无云端请求，均不构建或运行游戏 Mod。开发者可用 `npm run behavior:compile -- /absolute/path/input.json` 处理外部规格；自然语言分析到规格的自动桥接尚未接入。[命令与输入合同](docs/execution-kernel.md)

公开 GitHub Pages 展示界面与说明，不收集 Key，也不连接本机服务。代码经测试和构建后同步 GitHub；网页发布、工具完成和真实游戏转换成功分别记录。

## 后续开发主线

下一步连接自然语言分析与可验证规格，接入有证据的检索、资源和宿主工具，再实现真正的 Mod 后端与游戏验收。动态模型 Planner 尚未接入。内核编译与游戏转换分别验收；新增支持必须有接口依据、精确环境、特征损失说明与真实记录。

当前宿主接入的首要阻塞是保留参数、可追溯且可观察的本地启动方式；此前的原生脚本编译与状态写入不能替代真实交互。开发者探针命令及边界见 [宿主预检](docs/host-preflight.md)。
