# GameBridge 审查修复与下一轮优化方向

版本：0.5.1 Alpha。日期：2026-10-30（Asia/Shanghai）。本轮修复审查确认的五项缺陷，没有增加游戏宿主，也没有调用收费模型。真实动作 Mod 后端、真实 Mod 编译与游戏运行仍未验收。

## 五项修复

| 问题 | 修复行为 | 回归证据 |
| --- | --- | --- |
| 切换供应商地址复用默认 Key | 默认凭据绑定配置的 HTTPS origin，三个付费端点统一解析；更换域名或端口且没有显式新 Key 时先阻断。界面清除跨 origin 的手动旧 Key | 假凭据覆盖新旧分析和源码任务，阻断时模型生成器调用为 0；同 origin 的大小写与默认端口等价可用，新 Key 可显式选择新供应商 |
| 源码守卫只检查字符串 | 固定 SMAPI 的字段、数据类、Entry 接线与清理壳；动作处理器必须以精确条件及退出分支开头 | 恒假、恒真包装、空分支、反转分支、前置副作用、守卫移位和额外入口被拒绝；历史已接受源码仍通过新的有限检查 |
| 大蓝图附加本地字段后复验失败 | 模型 proposal 仍限 64 KiB，规范化结果另限 80 KiB；返回前检查规范化大小，宿主检查同步预算 | 59,015 字节 proposal 加 8,000 字符原始需求，规范化后 67,359 字节，复验、序列化、宿主检查与 HTTP 下载均通过；宿主仍 blocked |
| 默认回放漏命中连段正例 | 在切换窗口内选择可发生命中的时刻，同 tick 先命中后输入；补充后续动作的有限路径 | 命中窗口 `[3,5)` 与转换窗口 `[0,10)` 产生有效正向回放；循环、时长、资源和场景数量有界 |
| 旧分析取消后仍保存结果 | 新旧分析均在等待后和保存前检查取消 | 忽略取消的假生成器晚返回时不再序列化或保存；后续请求可正常运行 |

凭据测试仅使用假 Key 和本地替身，没有向其他域名发送真实 Key。默认凭据保护由后端执行，界面提示不作为唯一防线。

源码修复限定了更窄的结构合同：合同之外的等价 C# 也可能拒绝。它不是任意 C# 控制流证明、沙箱或行为正确性证明，不允许自动安装或执行 DLL。补充检查还修正了单行注释的换行处理，避免 C# 的 CR、LF、NEL、LS、PS 与筛查器解释不同；原始编译源码和字符串内容保持不变。[C# 官方词法规范](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/lexical-structure#632-line-terminators)

两套界面还修复了配置失败时仍启用操作的状态边界。前端回归使用真实 UI 脚本和小型假 DOM，验证默认地址提示、等价 origin、跨域清 Key、阻止空 Key 提交和坏配置禁用；这些测试不等于真实浏览器的完整验收。

## 验证口径

本轮回归覆盖五项原始复现和相关边界；无模型调用的八个固定动作规则检查继续通过。自动回放最多 64 个场景，搜索最多 136 个候选，每条路径最多 16 个不同动作；只能提供有限可行路径，资源或时间受限时可能缺少覆盖，不能据此宣称全图验收。

本地 `npm test` 共 164 项通过，0 失败、0 跳过；`npm run build` 通过。较审查时增加 23 项回归测试。八项固定动作检查也通过，模型调用为 0。本轮未进行真实 Mod 编译或游戏验收。

此前三次真实模型抽检和需求分类问题仍保留在 [0.5.0 验收记录](action-workbench-acceptance.md)。本轮没有新的真实模型稳定性证据，也没有真实游戏构建或运行证据。`realModBuild=not_run`、`game=not_run`、`readyToInstall=false`。

## 下一轮只聚焦宿主准入验证

目标是确认一个 macOS 可用宿主，能否将明确动作规则落实为真实武器交互。当前新动作链只导出 JSON，旧 Mod 管线只处理 SMAPI Buff；两者之间的宿主代码后端仍未实现，动作合同也缺动画、位移、判定与伤害绑定。

建议交付按以下三关收敛：

1. **准入检查包**：确认现有可用游戏、二维或三维目标、精确版本、Mac 架构、SDK、真实安装引用、允许接口和构建边界。缺环境时输出 blocked，不收费生成。tModLoader 只是研究候选，不默认玩家接受二维路线。
2. **最小真实动作探针**：用受信任固定模块验证输入、可见动作、真实目标命中、资源消耗、连段或取消、受击中断及退出恢复。固定探针仅作为工程基线，不算 AI 转换器完成。
3. **连接自动制作**：探针通过后，按真实接口补动作合同及蓝图到宿主 Mod 后端，优先让受信任的宿主运行时代码执行受限规则数据；缺能力时明确待适配。冻结来源动作规格，再验收三种不同自然语言需求及一次修改。验收条件独立于模型输出制定。

tModLoader 候选的工具目标会引用真实安装库、加载分析器，并在构建后启动打包程序；还需要其开发指南要求的对应 SDK。不能直接套用现有 SMAPI 编译器。[候选与环境说明](host-environment.md)

版本或架构无法匹配、核心接口不可用、动作只能退化为 Buff、接入超出允许的 Mod 路径，或二维表现不符合目标时，停止该候选并保留证据。当前不需要用户购买游戏、准备 Windows 或上传游戏文件。
