# GameBridge 动作规则与宿主门控

实现版本：0.5.1 Alpha。更新于 2026-10-30（Asia/Shanghai）。已实现从自然语言需求到声明式动作规则、规则回放、宿主能力检查和设计导出的流程；本轮修复见 [审查修复记录](review-fixes.md)。尚无动作宿主适配器，不生成可安装的动作 Mod。既有 SMAPI 工程与编译修复位于独立管线测试入口。

## 玩家可以使用的功能

本地运行 `npm run dev` 后，首页可以调用已配置的 DeepSeek，一次请求生成动作设计，不自动重试。需求、来源、宿主、资源缺口和规则映射一起保留。没有游戏环境也可设计规则；真实制作仍被宿主门控阻断。

公开页面可以载入三种项目自有示例并回放，不调用模型、不接收 API Key、不连接本机服务：命中后才能连段、挥空也可连段、攻击期间不能闪避取消。它们不是商业游戏的移植成果。玩家可导出动作设计 JSON，文件标记 `action-design-not-a-mod` 或 `action-design`，不包含 DLL。

## 规则表达和时间语义

蓝图保留宿主和来源、目标版本、来源引用、逐项需求、体力、起始输入、动作、切换条件和资源依赖。需求映射到动作仅表示结构关联；完整语义覆盖和来源保真仍为未验证。无法表达的需求可以返回空动作集合，并保留缺口，不自动换成示例或 Buff。

当前动作种类只有 `attack` 和 `dodge`。攻击有起手、命中窗口和后摇；输入可在指定窗口切到另一个动作，条件为总是允许或本动作已收到模拟命中。闪避目前只是带时长和消耗的状态，**没有真实位移、碰撞、无敌帧、动画或伤害执行**。受击事件仅根据动作的 `interruptible` 规则中断它，不模拟死亡、硬直时长或敌人 AI。

时间单位是离散 tick，尚未绑定宿主帧率。每个 tick 先完成到期动作，再按原数组顺序处理该 tick 的事件，最后只在空闲状态恢复体力。窗口采用前闭后开 `[start, end)`；同 tick 的命中和输入顺序会影响结果。命中事件只在攻击的有效窗口里确认，进入下一动作时清空。

模型返回的是数据，不执行表达式、脚本或任意命令。最多 16 个动作、每动作 8 个切换、32 个需求。模型 proposal 上限仍为 64 KiB；附加原始需求和本地派生字段后的规范化蓝图另限 80 KiB，且其中的模型数据仍须满足原预算。规范化结果在首次接受前再次检查，以便后续校验、导出与宿主评估一致。动作最长 600 ticks，单场景最长 3600 ticks、256 个事件，轨迹最多 2048 条。未知字段、畸形结构、无效引用、无法到达的动作、重复或重叠输入窗口、非有限数字及伪造验收字段都会拒绝。

默认回放会选择有效的命中与切换时刻，同 tick 先命中再输入；也会为后续动作选择有限可行路径。搜索最多处理 136 个候选，路径最多包含 16 个不同动作，自动生成最多 64 个场景。资源或时长不足的路径可能没有覆盖，不能把回放完成或场景数量当作全图覆盖证明。此前验收中的 8/6 个默认场景属于旧版本记录；八个固定规则断言仍保持独立。

## 宿主能力检查

系统从规则推导输入、动画、命中、伤害、位移、资源、连段、中断和恢复等接口需求。Bannerlord 是研究候选，SMAPI 只保留已有管线能力，其他宿主显示未知。当前所有动作宿主均为 `blocked`，没有已验证的动作能力或精确适配版本。

填写游戏与工具版本只是元数据，不会变成真实安装或兼容性证据。模型提供的 `readyToInstall`、`game` 等本地字段不能把状态升级。资源、来源规格、版本和未适配需求分别保留。[准备真实游戏环境](host-environment.md)

## 调用与数据边界

一次动作分析最多一次模型请求，输出上限 8192 tokens、响应上限 256 KiB、截止 120 秒。失败不会生成模板冒充模型结果，也不会自动重试。取消会阻止晚返回结果被校验或保存；已发出的请求仍可能计费。

本地模型配置和请求中的 Key 不进入蓝图、下载、日志或模拟。服务器同时检查环境 Key 与临时 Key 的回显；模拟场景中的意外 Key 也会被拒绝。公开页面不提供 Key 设置。工程、依赖和 C# 构建权限沿用原有锁定方式；新增动作数据不会扩大模型执行权限。

默认 Key 绑定到配置的 HTTPS origin。修改域名或端口时必须提供对应 Key，三个付费入口均在调用前检查；同域名大小写、尾斜杠与默认 443 端口按同一 origin 处理。界面跨 origin 修改地址时会清除手动 Key 并更新提示。新旧分析接口取消后均丢弃晚返回的结果。

旧需求分析现在共享一份机器可读结构规范与完整示例，错误区分 JSON、结构和语义，并提供不含原始值的字段诊断。严格拒绝错误资源数组，不把对象转成字符串。提示和诊断改进本身不构成模型稳定性证明，真实抽检另行记录。

## 接口与验收

| 接口 | 作用 |
| --- | --- |
| `GET /api/action-hosts` | 读取候选目录，不是兼容清单 |
| `POST /api/action-example` | 三种非 AI 自有规则示例 |
| `POST /api/action-plans` | 一次模型分析与动作规则设计 |
| `POST /api/action-plans/:id/simulate` | 使用默认或指定合成场景回放 |
| `GET /api/action-plans/:id/download` | 下载设计 JSON，不是 Mod |

`npm run verify:actions` 不调用模型，检查八个固定行为场景。`npm run verify:actions -- --live` 则追加最多三次真实请求：一次旧接口新需求分析、两次不同动作规则设计，逐项保存成功和失败，原始安全产物仅留在被 Git 忽略的本地目录。旧计划回放不计为新分析；模型动作回放不自动证明其满足自然语言要求。

本轮验收见 [动作制作验收记录](action-workbench-acceptance.md)。规则测试通过、编译通过和游戏验收各自独立；当前 `realModBuild=not_run`、`game=not_run`、`readyToInstall=false`。
