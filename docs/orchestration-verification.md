## 本地契约与集成检查

`npm test` 全套 **106/106 通过，0 跳过**，`npm run build` 通过。检查使用项目自有数据、临时磁盘目录和模拟模型响应，不是实际游戏或云端模型验收。覆盖：

- 任务图循环、缺失依赖、逻辑引用与有界 JSON 拒绝；模型不能提交状态、权限或命令。
- 版本化适配器、平台和内容能力匹配；未绑定操作、缺能力、歧义和伪造游戏证据保持阻断。
- 依赖并发、调用前落盘预留、有限尝试、预算增加、完成任务去重。
- 真实子进程终止、遗留写入租约恢复、原子快照并发观察、损坏和凭据拒绝。
- 取消、超时、晚到输出丢弃，以及关闭服务期间创建/恢复的竞争。
- HTTP、本机 Host/Origin、供应商 origin/model 绑定、下载和公开页面边界。

并发调度测试使用确定性 barrier，避免将磁盘负载下的短暂时间差当作调度失败。线程内异步 handler 的观察有截止时间；同步 CPU 死循环不在当前实现的抢占范围内。校验和用于检测损坏，不能防止同一用户改写本机文件。

## 验收边界

当前报告固定为 `scope=orchestration-only`、`realModBuild=not_run`、`game=not_run`、`readyToInstall=false`。通用协议、可靠调度和角色间数据传递已具备本地回归证据；自动工程生成、编译修复、资源转换、游戏适配与游戏实测尚未接入。

下一步优先给角色接入受约束、可记录证据的检索与资源/环境检查工具，再扩展动态重规划和真实执行适配器。真实模型的合同失败需要保留为失败，并改进可解释诊断；不应以放宽合同、静默删需求或自动收费重试取得表面成功。
